# WebPass v1.1.0 易用性修正设计规格

## 目标

在不修改密码安全流程和数据库 schema 的前提下改善服务器资产页：把“查看密码”提升到“编辑”和“Ping”旁边；允许用户安全地选择 `1–500` 的每页数量；允许管理员在完整地址池中直接 Ping 未登记地址，且不创建或修改服务器资产。

## 范围

本次只修改服务器资产页、应用层 Ping 工作流、审计展示标签、必要样式和聚焦测试。密码查看后端、权限、二次验证、CSRF、密码自动隐藏、子网管理、资产登记、现有服务器 Ping 历史及部署流程保持不变。

不允许修改 EF Core 实体、数据库映射、模型快照或 migration。

## 当前行为与根因

### 查看密码位置

查看按钮和密码面板目前位于名为“更多操作”的 `details` 内。JavaScript 和后端安全流程并不依赖该嵌套，因此根因只是 Razor 页面结构。

### 每页数量

筛选表单把 `Query.Take` 和 `Query.Skip` 都作为隐藏字段。页面把绑定后的 `ServerListQuery` 直接传给 `ServerAssetService.ListAsync`，而服务的防御性契约会在 `Take` 超出 `1..500` 时抛出异常。因此手工构造 URL 可以让非法值进入服务；提交筛选时也会保留旧偏移量，而不是回到第一页。

### 未登记地址 Ping

完整地址池中的空闲行在查询时临时生成，没有 `ServerAssetId`。现有 Ping 服务只接受服务器资产 ID，必须验证已登记资产，始终创建带必填 `ServerAssetId` 的 `PingResult`，页面反馈也依赖资产 ID 定位。因此当前设计无法在不错误创建资产或污染服务器 Ping 历史的情况下探测空闲地址。

## 选定设计

### 服务器行操作

把已登记服务器的允许操作放入专用 `table-actions` 容器，并按以下顺序渲染：

1. `编辑`
2. `Ping`
3. `查看密码`
4. `更多操作`

把现有查看按钮和密码面板移出更多操作菜单，但不修改其 ID、data 属性、CSRF token 来源、脚本、接口或超时行为。只有具备归档权限时才渲染“更多操作”，其中只保留现有归档确认。增加最少量 flex 样式，使主操作视觉并列，Ping 反馈和密码面板仍作为独立块显示。

### 每页数量规范化

把隐藏的 `Query.Take` 改为有标签的数字输入，设置 `min="1"` 和 `max="500"`。筛选表单固定提交 `Query.Skip=0`，因此应用筛选或修改每页数量时都会从列表开头加载。上一页和下一页继续携带规范化后的 `Query.Take`。

在调用 `ServerAssetService.ListAsync` 前规范化页面绑定的查询：

- 把 `Take` 限制在 `1..500`；
- 把负数 `Skip` 规范化为 `0`，形成一致的安全边界；
- 非数字等绑定错误继续保留现有 ModelState 提示。

`ServerAssetService.ValidateQuery` 保持不变，使非 UI 调用者继续受严格防御性契约保护。

### 共享 Ping 探测核心

新增仅属于应用层的 `PingProbeResult`，保存规范 IP、规范化结果、延迟和安全错误码。重构 `PingService`，让已登记和未登记操作共享一个私有传输执行路径，统一负责：

- 配置的超时时间；
- 现有进程级并发门；
- 现有单用户一分钟额度；
- `IPingTransport` 调用；
- 传输异常转换；
- 结果和错误码规范化。

已登记服务器的 `ExecuteAsync` 公共契约和持久化行为保持不变：加载并验证资产，调用共享探测核心，写入 `PingResults`，写入现有 `PingExecute` 审计，并且不修改手工存活状态。

新增专用未登记地址操作，接收 `subnetId`、规范 IPv4 文本、操作人 ID 和取消令牌。消耗 Ping 配额前必须：

1. 检查 `PingExecute` 权限；
2. 加载启用的网段；
3. 要求目标是该网段内的规范 IPv4 可用地址；
4. 如果活动服务器资产已使用该地址，则拒绝请求。

探测完成后只写审计并返回 `PingProbeResult`。不得新增 `ServerAsset`、新增 `PingResult` 或更新任何资产字段。

### 空闲地址页面工作流

为服务器列表增加独立的空闲地址 POST handler 和表单。表单提交 `subnetId` 与 `targetIp`，继续强制使用 Razor Pages CSRF 防护。根据 Ping 和登记权限分别显示操作，形成 `Ping | 登记此 IP`。

空闲地址反馈使用不同于已登记服务器的 TempData key。使用反馈前验证反序列化内容；重定向回完整地址池模式，同时携带目标网段和精确 IP 搜索并固定 `Skip=0`；只在相同网段/IP 行旁显示结果。空闲地址反馈绝不提供“标记为存活”。

继续使用现有 Ping 结果中文格式。权限不足、目标无效、限频和未知失败均返回相同风格的安全中文响应，不暴露异常文本。

## 审计设计

复用现有 `AuditLogs` schema：

- `Action`：`PingUnregisteredAddress`
- `ObjectType`：`SubnetAddress`
- `ObjectId`：规范目标 IP
- `Result`：规范化 Ping 结果
- payload：`subnetId`、`targetIp`、`outcome`、`latencyMilliseconds` 和安全 `errorCode`

为新操作和对象类型补充中文标签。payload 不包含敏感信息。参数验证失败不伪造探测结果；每次真正完成的传输尝试，包括超时、不可达和规范化内部错误，都写入审计记录。

## 数据模型、Migration 与历史回填

`PingProbeResult` 不是 EF Core 实体。`PingResult.ServerAssetId` 继续为必填，`PingResults` 表继续只保存已登记资产的历史。现有 `AuditLogs` 字符串字段与 JSON payload 已能承载新审计值。

不创建 migration，不修改 `WebPassDbContextModelSnapshot`。不回填历史数据：现有资产、Ping 历史和审计保持不变，空闲地址探测审计只从部署后开始产生。

发布仍遵循 `DEPLOYMENT.md`，包括构建并执行与提交匹配的 migration bundle。由于没有新 migration，本功能不会通过 bundle 产生 schema 或数据迁移。

## 测试

- 服务器页面标记测试验证操作顺序、查看密码位于更多操作之外、更多操作只包含归档、权限组合、可见数字输入、`1..500` 限制和筛选 `Skip=0`。
- 查询集成测试验证过低/过高值在进入服务前被限制、负偏移安全、分页保留规范化 `Take`，且错误绑定提示继续显示。
- Ping 服务测试验证权限、规范网段校验、活动资产占用拒绝、超时传递、不同目标共享限频和并发、结果规范化、审计内容，以及空闲探测不会修改资产或 `PingResults`。
- 页面集成测试验证 CSRF、安全错误、重定向和行级反馈、操作权限组合、不出现标记存活，以及数据库不受污染。
- 现有密码查看可执行 DOM 测试和已登记服务器 Ping 回归测试保持不变并必须通过。
- 先运行聚焦测试，再运行单元和集成项目，最后在支持离线 migration bundle 与 SQL Server 测试的环境中运行完整解决方案测试。

## 未采用方案

- 为空闲地址 Ping 新建独立 Razor Page 虽可隔离端点级限流，但会增加路由并重复资产页专用反馈流程；服务层已拥有两个资产页操作需要共享的限流。
- 通用目标/持久化策略层次可支持未来探测类型，但属于不必要抽象，超出本次修正范围。
- 把 `PingResult.ServerAssetId` 改为可空会混合两类历史，引入 migration 和回填决策，并直接违反不修改 schema 的要求。

## 风险

- 现有地址池在不包含归档记录时，会把只有归档资产历史的地址视为空闲。新操作沿用“没有活动登记”的语义，并且不修改归档数据。
- 服务检查活动资产后、ICMP 执行期间，地址仍可能被登记。探测过程依然不会修改资产或 Ping 历史；跨网络 I/O 持有可串行化数据库锁会带来更差的运维权衡。
- ASP.NET 端点限流标记在已登记服务器的独立 Ping 页面上，而资产列表 Ping 使用服务层额度。若给整个资产 PageModel 添加限流，会同时限制登记和归档 POST，因此两个资产列表 Ping handler 继续共享服务层限流。
- 新审计操作和对象类型必须同时提供 UI 标签，否则现有审计页会按设计显示未知标签。
