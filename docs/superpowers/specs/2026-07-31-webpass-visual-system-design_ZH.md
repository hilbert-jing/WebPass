# WebPass 全站视觉与交互系统设计

## 1. 文档状态

- 日期：2026-07-31
- 状态：视觉方向、视觉基础、导航布局、交互动效与敏感操作体验均已获用户确认
- 产品：WebPass 局域网服务器资产与密码管理系统
- 实现范围：`src/WebPass.Web/Pages` 下全部用户可见页面，以及相关处理端点产生的界面反馈
- 技术边界：ASP.NET Core Razor Pages、服务端渲染、少量原生 JavaScript，不引入 React、Vue 或依赖公网的资源

## 2. 设计目标

WebPass 面向少量内网运维人员，承载约 500 台服务器、多个 IPv4 网段、访问凭据、导入导出与审计操作。新版界面应在长时间、高密度使用中保持清晰，同时让安全边界和系统状态容易理解。

本次设计目标：

1. 为所有页面建立统一、可辨识的“静稳运维”现代控制台风格。
2. 使用浅色工作区保证表格与表单的可读性，使用深色导航建立控制台身份。
3. 将服务器、网段、IP、状态、权限和敏感操作之间的关系表达清楚。
4. 在不改变后端权限与业务处理流程的前提下，重组导航、筛选、表格操作、表单分组和确认体验。
5. 让 Ping、密码查看、密码导出、归档、禁用和删除等操作获得准确、可行动的反馈。
6. 保证键盘、屏幕阅读器、减少动态效果和窄屏环境可用。

## 3. 非目标

- 本轮不增加暗色主题；主题基线为“深色导航 + 浅色工作区”。
- 不增加中英文切换；界面统一使用简体中文。
- 不改变认证、授权、CSRF、限流、加密、审计和并发控制规则。
- 不把应用改造为单页应用，也不引入新的前端框架。
- 不增加当前后端尚不支持的批量操作、实时推送、自动 Ping、图表分析或审计筛选能力。
- 不为 `/health`、`/logout`、`/servers/{id}/ping` 和 `/secrets/reveal` 等处理端点虚构独立业务页面。

## 4. 设计方向

### 4.1 风格定义

采用已确认的 C 方案“静稳运维”：

- 理性、专业、精密，但不使用高压、霓虹或“黑客终端”视觉。
- 轮廓清晰、间距稳定、圆角克制；主要内容依靠色面和边框分层。
- 信息密度高于普通企业后台，但通过字体角色、列对齐和操作收纳保持安静。
- 深海蓝代表系统框架；轨迹蓝代表定位与主操作；绿色与琥珀色只表达状态。
- 不使用装饰性渐变；阴影仅用于抽屉、弹出确认和其他真实浮层。

### 4.2 签名元素：IP 地址脉络

WebPass 的唯一品牌化视觉动作是“IP 地址脉络”：一条由地址节点构成的细轨道，用于表示 CIDR 地址池、已登记地址和当前检测位置。

使用场景：

- `/servers` 页展示当前网段的已用地址与可用地址关系。
- `/subnets` 页在预览 CIDR 时展示网络地址、广播地址和可用地址范围。
- Ping 运行时让一个高亮节点沿轨道完成一次短促扫描。
- 登录页品牌区可使用静态、低对比度的地址脉络作为产品识别。

约束：

- 页面静止时不循环播放环境动画。
- 仅在首次进入、Ping 进行中或地址使用率变化时播放一次。
- 启用 `prefers-reduced-motion: reduce` 时取消位移和循环，以静态高亮表示状态。

## 5. 设计令牌

### 5.1 色彩

核心色限制为六个命名值：

| 令牌 | 色值 | 用途 |
|---|---|---|
| 深海导航 | `#1C3147` | 全局侧栏、敏感流程标题区 |
| 雾蓝工作区 | `#F4F7FA` | 页面背景、低对比度内容区 |
| 主文本 | `#182B3A` | 标题、正文、关键数据 |
| 轨迹蓝 | `#2E75A8` | 主操作、焦点、活动导航、IP 轨迹 |
| 存活绿 | `#27856A` | 成功、存活、启用、连接正常 |
| 告警琥珀 | `#C8862B` | 异常、风险提示、需要关注 |

派生色可以通过透明度或明度变化生成边框、悬停和背景，但不得引入新的品牌主色。危险操作使用低饱和红色派生色，例如文字 `#973E43`、背景 `#F9E9EA`；红色只用于破坏性操作和阻断错误。

颜色不是唯一信息载体。状态必须同时包含文字或图形标记，例如“存活”“异常”“未知”“停用”。

### 5.2 字体

应用部署在离线 Windows 内网，不依赖 Google Fonts 或其他外部字体服务。

- 中文标题与正文：`"Microsoft YaHei UI", "Segoe UI", sans-serif`
- 拉丁标题与大数字：`Bahnschrift, "Microsoft YaHei UI", sans-serif`
- IP、CIDR、延迟、关联编号和倒计时：`"Cascadia Mono", Consolas, monospace`

建议字号：

| 角色 | 桌面字号 | 字重 |
|---|---:|---:|
| 页面标题 | 28 px | 600 |
| 区块标题 | 18 px | 600 |
| 正文 | 14 px | 400 |
| 表格正文 | 13 px | 400/600 |
| 辅助说明 | 12 px | 400 |
| 数据标签 | 11 px | 600，等宽 |

正文行高不低于 1.6；表格行高由 44–48 px 的行尺寸保证，不通过压缩文字行高制造密度。

### 5.3 间距、圆角与阴影

- 基础间距单位：4 px。
- 页面水平留白：桌面 28–32 px，平板 20–24 px，手机 14–16 px。
- 常规控件圆角：7 px；内容容器：8–10 px；胶囊标签只用于短状态。
- 常规卡片和表格仅使用 1 px 边框，不使用阴影。
- 抽屉、弹出确认、下拉菜单等浮层可以使用轻阴影。
- 同一页面不堆叠多层卡片。页面、区块、控件三级层次已经足够。

## 6. 全局应用框架

### 6.1 桌面导航

桌面宽屏使用 218–232 px 深色侧栏。侧栏包含：

1. WebPass 标记和“基础设施控制台”说明。
2. 按任务分组的权限可见导航。
3. 底部账户、会话状态和退出入口。

导航分组：

| 分组 | 页面 |
|---|---|
| 资产作业 | 服务器资产、网段管理 |
| 数据流转 | 数据导入、数据导出 |
| 安全治理 | 审计日志、用户与权限、密码导出 |

现有逐用户权限继续决定链接是否出现；导航隐藏不构成安全控制，服务端授权仍是最终裁决。

活动项使用浅一层蓝色底和左侧/图标高亮，不依赖发光效果。导航图标采用本地内联 SVG，统一 18 px、1.5 px 描边，不使用表情符号或外部图标字体。

### 6.2 顶栏

顶栏高度约 48 px，包含：

- 当前分组和页面的面包屑。
- 内网连接/会话状态。
- 当前用户和退出操作。

顶栏不重复侧栏中的全部导航。退出使用 POST 表单，保持现有 CSRF 防护。

### 6.3 内容区骨架

常规页面依次包含：

1. 页面标题、单句说明和一个主操作。
2. 可选的 IP 地址脉络或摘要信息。
3. 筛选/命令条。
4. 主内容表格、表单或流程区域。
5. 分页、结果数量或辅助说明。

只有确实存在主操作时才显示标题区按钮；不为每页强行添加按钮或统计卡片。

### 6.4 响应式行为

- `>= 1280 px`：完整侧栏和多列内容。
- `768–1279 px`：侧栏收窄为约 72 px，只显示图标；焦点和悬停显示文字提示。
- `< 768 px`：侧栏变为顶部按钮打开的导航抽屉；表单变为单列；表格保留关键列并允许水平滚动。
- 服务器资产属于桌面优先场景，窄屏不把每一行强制转换成大卡片，以免失去跨行比较能力。
- 所有浮层在手机宽度下使用全宽底部面板或独立内容区。

## 7. 页面模板

### 7.1 高密度列表模板

用于 `/servers`、`/subnets`、`/audit` 和 `/admin/users`。

- 表头使用浅蓝灰色面，支持清晰的列对齐。
- IP、CIDR、时间、关联编号采用等宽字体。
- 行悬停只改变浅色背景并显示左侧 2 px 轨迹蓝定位线。
- 行内只保留 1–2 个高频操作；其他操作进入带文字标签的更多菜单。
- 操作菜单必须可通过键盘打开，`Escape` 关闭，焦点关闭后返回触发按钮。
- 空状态位于表格容器内，说明为何为空并提供可执行下一步。

### 7.2 分组表单模板

用于服务器编辑、网段创建/编辑、用户创建/权限、导入和导出。

- 字段按用户能够理解的对象分组，不按数据库字段顺序排列。
- 标签始终可见，不用占位符代替标签。
- 字段错误显示在字段下方；页面顶部保留错误摘要并链接到对应字段。
- 主操作使用轨迹蓝；次操作使用浅蓝灰；破坏性操作与保存区域物理分离。
- 保存时按钮进入明确的忙碌状态，阻止重复提交，但服务端幂等与并发控制仍必须保留。

### 7.3 专注验证模板

用于 `/login`、`/secrets/reauthenticate` 和 `/error`。

- 不显示完整业务侧栏，避免在登录或敏感验证中分散注意力。
- 桌面端左侧为深海蓝品牌区，右侧为单一任务卡片；手机端仅保留任务卡片和小型品牌标记。
- 页面只包含完成当前任务所需的信息和操作。

## 8. 逐页规格

### 8.1 全局布局 `_Layout.cshtml`

- 将根语言设置为 `zh-CN`。
- 登录用户看到权限裁剪后的分组侧栏、顶栏和内容区。
- 未登录页面不渲染业务侧栏。
- 页面标题格式保持“页面名称 - WebPass”，页面名称改为简体中文。
- 引入本地站点样式和必要的原生 JavaScript；不引用 CDN。
- 提供“跳到主要内容”链接、清晰焦点样式和 `aria-current="page"`。

### 8.2 登录 `/login`

- 标题：“登录 WebPass”；说明：“使用内部账户进入基础设施控制台。”
- 字段：“用户名”“密码”；主操作：“登录”。
- 登录错误显示在表单内，不透露用户名是否存在。
- 登录按钮提交后显示“正在登录”，避免重复提交。
- 品牌区使用静态 IP 地址脉络；不得暗示公网连接或云服务。

### 8.3 服务器资产 `/servers`

页面标题：“服务器资产”；说明：“登记、检索并维护业务服务器与访问凭据。”

页面结构：

1. 标题区主操作“登记服务器”。
2. 当前网段的 IP 地址脉络；未选择网段时显示全局摘要，不伪造精确地址池。
3. 命令条：搜索、网段、状态、“包含已归档”“显示完整地址池”和“应用筛选”。
4. 服务器表格。
5. 结果数量和上一页/下一页。

表格列：业务 IP、位置、状态、计算机名、系统名称、操作系统、数据库、备注、操作。窄屏优先保留业务 IP、计算机名、状态和操作，其余列通过水平滚动访问。

交互：

- “登记服务器”打开右侧表单抽屉；现有 Create handler 和字段保持不变。
- 通过空闲 IP 进入时自动打开抽屉并预填业务 IP。
- 抽屉在无 JavaScript 时退化为页面内可见表单，不阻断登记。
- 高频操作为“查看”和“Ping”；编辑、标记存活、归档进入更多菜单。
- 没有查看密码权限时，不渲染查看入口和相关防伪表单。
- 尚未完成二次验证时，“查看密码”引导至 `/secrets/reauthenticate`，返回地址保持 `/servers`。
- 密码显示在对应行的受控展开区，不进入全局 Toast；最多 30 秒，并在切页、隐藏、退出或会话失效时清除。
- 归档前显示 IP、计算机名、系统名称和影响说明；按钮文案为“归档服务器”。

### 8.4 服务器编辑 `/servers/{id}/edit`

- 使用分组表单，不使用抽屉。
- 分组一“身份与位置”：业务 IP、位置、计算机名。
- 分组二“系统信息”：系统名称、运行状态、操作系统版本、数据库版本。
- 分组三“凭据与备注”：新密码、备注。
- 密码字段说明：“留空则保留当前密码”，不得显示现有密码。
- 页底固定操作区包含“保存更改”和“返回服务器资产”。
- 并发冲突时保留用户输入，显示最新数据与明确的重新确认入口，不静默覆盖。
- AssetId 缺失时显示可行动空状态，并链接回服务器资产页登记预填 IP。

### 8.5 Ping 处理 `/servers/{id}/ping` 与服务器页 Ping handler

这些路由/handler 不形成独立可见页面。结果回到服务器资产上下文中显示：

- 请求提交后，行内按钮显示“正在检测”，IP 脉络完成一次扫描。
- 成功：“检测成功 · 可达，延迟 18 ms”，随后才显示独立的“标记为存活”操作。
- 超时和不可达属于检测结果，使用琥珀提示，不进入系统错误页。
- 权限不足、非法目标、限流或服务端异常使用可行动错误信息；不显示内部异常详情。
- Ping 成功不得自动修改人工状态。

### 8.6 网段管理 `/subnets`

- 标题：“网段管理”；主操作：“添加网段”。
- 页面顶部展示所有网段的紧凑列表；名称和 CIDR 为主识别信息。
- 添加网段使用右侧抽屉，字段分为基本信息和启用状态。
- “预览范围”在抽屉内生成地址脉络，明确列出网络地址、广播地址和可用地址数。
- 编辑使用表格下方的行内展开面板，避免每行同时显示完整表单。
- 启用/停用为次级确认；删除使用危险确认，并说明有关联服务器时无法删除。
- 重叠错误明确指出冲突的 CIDR 或网段名称。

### 8.7 数据导入 `/imports`

- 标题：“导入服务器数据”；说明支持 CSV/XLSX、10 MB、5,000 行。
- 上传区使用清晰边框和标准文件输入；拖放是增强功能，键盘文件选择始终可用。
- 预览后显示四项摘要：新增、更新、跳过、错误。
- 错误列表使用表格列出行号、字段和原因，绝不回显密码内容。
- 存在阻断错误时禁用并解释“提交导入”不可用的原因。
- 无阻断错误时主操作为“提交导入”，并再次说明提交会在单一事务中整体完成。
- 预览过期或应用重启导致预览失效时，明确要求重新上传。

### 8.8 普通导出 `/exports`

- 标题：“导出服务器数据”。
- 页面顶部使用绿色安全说明：“普通导出不包含服务器密码。”
- 表单字段：搜索范围、网段、状态、格式。
- 提交前显示简短范围摘要；主操作按格式命名为“下载 CSV”或“下载 XLSX”。
- 下载开始后不显示虚假的完成进度。后端返回文件后保持页面可再次调整条件。

### 8.9 审计日志 `/audit`

- 标题：“审计日志”；说明日志只读且不可在此修改或删除。
- 列：时间、操作人、动作、对象、结果、关联编号。
- 时间使用本地统一格式并保持时区清晰；关联编号使用等宽字体并提供复制按钮。
- 成功和失败同时显示文字；失败使用低饱和红色标记，不隐藏失败记录。
- 当前后端没有筛选与分页能力，本轮不新增假筛选控件；待后端能力扩展时再增加。
- 空状态：“尚无审计记录”，不提供创建按钮。

### 8.10 用户与权限 `/admin/users`

- 标题：“用户与权限”；仅管理员可见。
- “创建普通用户”进入顶部折叠面板或右侧抽屉，主列表保持可浏览。
- 用户表格列：用户、角色、状态、权限摘要、操作。
- 普通用户权限通过行内展开面板编辑，以功能中文名称分组；不直接把枚举代码作为主要文案。
- 管理员行显示“管理员拥有全部权限”，不显示无效的权限复选框。
- 创建和重置密码继续遵循当前后端的系统预设初始密码策略；本轮不虚构一次性随机密码流程。
- 重置前核对用户名和影响，成功后显示“密码已重置为系统预设初始密码”；界面不回显预设密码，也不把密码写入 Toast、日志或 URL。
- 启用/禁用先显示用户身份和影响；禁用使用琥珀而不是破坏性红色，因为账号可恢复。
- 保存权限后显示具体用户和已更新的权限数量。

### 8.11 管理员密码导出 `/admin/password-export`

- 标题：“导出服务器密码”；仅管理员可见。
- 顶部琥珀警示明确说明文件包含明文密码及受控介质要求。
- 选择范围后显示摘要：筛选条件、文件格式 XLSX、将记录的审计信息。当前后端未向页面提供准确数量，因此首轮界面不显示预计服务器数量。
- 当前密码二次验证仍有效五分钟；验证入口复用 `/secrets/reauthenticate`。
- 主操作：“确认并导出密码”。不得使用模糊的“提交”或普通“下载”。
- 下载开始后提示后续保管责任，但不在页面历史、Toast 或前端日志中出现任何密码。

### 8.12 二次验证 `/secrets/reauthenticate`

- 使用专注验证模板。
- 标题：“验证当前密码”；说明：“验证通过后，可在当前会话中查看服务器密码 5 分钟。”
- 只显示当前密码字段、验证按钮和返回操作。
- ReturnUrl 必须继续由后端验证；界面不回显未经信任的目标地址。
- 成功后返回原页面，并显示“验证有效期剩余时间”的低强调会话提示。
- 失败使用表单内错误，不清空与错误无关的上下文。

### 8.13 密码 Reveal `/secrets/reveal`

这是受保护的数据端点，不添加独立页面或全局布局。前端调用必须：

- 使用现有防伪令牌和权限检查。
- 将明文仅写入目标行的专用 `output`。
- 使用 `aria-live="polite"` 宣布展示与隐藏状态，但避免屏幕阅读器反复读出密码。
- 在 30 秒、页面隐藏、导航、退出和会话失效时清空文本节点。
- 响应失败时显示原因类别和下一步，不显示服务端异常或敏感内容。

### 8.14 错误页 `/error`

- 使用专注验证模板的简化变体，不显示业务侧栏。
- 标题：“无法完成此请求”。
- 说明用户可以重试或返回服务器资产；保留关联编号用于支持人员排查。
- 关联编号使用等宽字体并可复制。
- 不显示堆栈、路径、数据库错误或其他内部细节。

### 8.15 Logout 与 Health

- `/logout` 保持 POST 处理端点，不设计独立页面；退出后返回登录页，并显示“已安全退出”。
- `/health` 保持机器可读的最小响应，不加载导航、字体、脚本或品牌动画。

## 9. 交互动效

### 9.1 时长

| 时长 | 场景 |
|---:|---|
| 120 ms | 按钮按压、焦点、表格行悬停 |
| 180 ms | 菜单、字段反馈、提示面板 |
| 240 ms | 抽屉、验证结果、状态切换 |
| 0 ms | 减少动态效果时的位移与循环 |

页面是服务端渲染，不模拟 SPA 路由。完整页面载入只允许内容区做一次不超过 180 ms 的透明度变化；不得逐行长时间交错出现。

### 9.2 状态反馈

- 按钮文字与结果文字使用相同动词，例如“保存更改”对应“更改已保存”。
- 成功 Toast 位于内容区右上角，自动关闭前保持足够阅读时间，并可手动关闭。
- 字段错误贴近字段；跨字段错误位于表单顶部。
- 敏感结果、并发冲突和阻断错误不得使用会自动消失的 Toast。
- 空状态说明原因与下一步，不使用情绪化或道歉式文案。

## 10. 敏感与危险操作

### 10.1 密码查看

1. 用户在服务器行请求查看。
2. 未有有效授权窗口时进入二次验证。
3. 验证成功后返回服务器列表。
4. 用户再次请求具体服务器密码。
5. 密码在行内受控区域显示，并启动 30 秒倒计时。
6. 倒计时、切页、页面隐藏、退出或会话失效时立即清除。

复制密码不延长时间。倒计时使用文字和环形进度共同表达；减少动态效果时环形进度按秒离散更新，不做平滑旋转。

### 10.2 密码导出

风险来自导出内容，因此使用琥珀警示和范围摘要，不用大面积红色制造恐慌。确认页必须在按钮之前说明：包含什么、数量范围、保存责任和审计行为。

### 10.3 归档、删除、禁用

- 确认面板必须显示具体对象身份，不使用孤立的“确定/取消”。
- 服务器归档显示 IP、计算机名、系统名称和归档影响。
- 网段删除显示名称、CIDR 和关联限制。
- 用户禁用显示用户名和登录影响。
- 主按钮使用具体动词：“归档服务器”“删除网段”“禁用用户”。

## 11. 可访问性

- 正文和控件达到 WCAG 2.2 AA 对比度目标。
- 所有交互均可通过键盘完成。
- 焦点环使用 2–3 px 轨迹蓝外框，不被 `overflow` 裁切。
- 使用语义化标题、表单标签、表格表头、`nav`、`main`、`dialog`/适当 ARIA。
- Toast 和 Ping 结果使用合适的 `aria-live`；阻断错误使用 `role="alert"`。
- 不通过颜色单独区分状态。
- 支持 200% 缩放，不让主操作或错误说明被遮挡。
- `prefers-reduced-motion` 下取消非必要动画。

## 12. 实现边界与组件划分

设计实现应拆成职责清晰的共享单元：

- 应用框架：侧栏、顶栏、面包屑、主内容容器。
- 页面标题：标题、说明、主操作。
- 命令条：搜索、筛选、视图切换。
- 数据表格：表头、行状态、操作菜单、空状态、分页。
- 表单：字段、帮助、错误、操作区。
- IP 地址脉络：静态网段信息与受控 Ping 动画。
- 反馈：Toast、行内结果、阻断错误、空状态。
- 敏感展示：二次验证提示、明文输出、倒计时和清理。
- 确认面板：归档、删除、禁用和导出范围确认。

这些单元只负责呈现和交互状态，不复制服务端权限判断或业务规则。服务端生成的权限结果、验证错误、并发冲突和安全响应是界面的数据来源。

## 13. 错误与降级策略

- CSS 未加载：页面仍保持语义顺序、可提交表单和可读表格。
- JavaScript 未加载：导航、GET 筛选和 POST 表单仍可用；抽屉退化为页面内表单；密码 Reveal 可以明确提示需要启用脚本，不能降低安全限制。
- Ping 请求失败：保留当前行数据和用户筛选，不刷新为未知页面状态。
- 文件下载失败：保留筛选条件，显示可重试错误。
- 会话过期：敏感内容先清理，再引导重新登录。
- 并发冲突：保留输入，展示最新服务端值，不自动覆盖。

## 14. 验证与验收

### 14.1 视觉验收

- 所有可见页面使用相同色彩、字体、间距、圆角和动作层级。
- 页面中不存在外部字体、图标、脚本或样式依赖。
- 服务器表格在 1366×768 下仍能完成搜索、查看状态和进入主要操作。
- 1920×1080 下内容宽度受控，不因拉伸产生过长文本行。
- 768 px 与 375 px 宽度下无不可达的按钮、确认区或错误信息。

### 14.2 交互验收

- 侧栏只显示当前用户获权入口，服务端仍拒绝越权请求。
- 所有表单可通过键盘完成，错误与焦点关系明确。
- Ping 反馈不修改人工状态。
- 密码在规定事件发生时清空，且不进入 Toast、URL、日志或错误文本。
- 归档、删除、禁用和密码导出均显示具体对象或范围。
- 减少动态效果设置生效。

### 14.3 回归验证

- 现有 Razor Page 路由、handler 名称、字段绑定、CSRF 和权限判断保持有效。
- 自动化测试继续覆盖登录、权限、资产、网段、Ping、导入导出、密码和审计流程。
- 新增针对导航可见性、中文页面标题、错误摘要、敏感内容清理和减少动态效果的测试。
- 使用真实浏览器检查桌面、平板、手机、键盘操作和 200% 缩放。

## 15. 已确认设计决策

- 风格：现代控制台中的“静稳运维”。
- 主题：浅色主工作区 + 深色导航。
- 语言：简体中文，IP、Ping、CIDR、CSV、XLSX 等技术名词保留英文。
- 改造深度：适度重构，保留后端流程，重组导航、筛选、表格操作、表单分组和敏感操作确认。
- 签名元素：IP 地址脉络。
- 动效原则：只解释状态，时长短促，完整支持减少动态效果。
- 页面范围：覆盖所有用户可见 Razor 页面；处理端点只定义其调用页反馈，不伪造独立界面。
