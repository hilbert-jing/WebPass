# WebPass 局域网服务器资产管理系统设计

## 1. 范围与目标

WebPass 部署在 Windows Server 局域网中，用户通过服务器 IP 对应的 HTTPS 地址访问。预期规模为 5 名用户、约 500 台服务器和 5 个 IPv4 网段。

第一版目标：

- 展示和维护所在位置、存活状态、计算机名、系统名称、业务 IP、服务器密码、操作系统版本、数据库版本和备注。
- 默认按业务 IP 的数值升序排列。
- 按 CIDR 管理 IPv4 网段，支持查看全部可用地址和已登记地址。
- 在线新增、编辑、归档和重新登记服务器。
- 在后端执行按需 Ping，显示结果但不自动改变人工存活状态。
- 加密保存服务器密码，并在授权用户二次验证后短时显示。
- 支持 Excel/CSV 导入、无密码的普通导出，以及管理员专用的加密备份与恢复。
- 使用应用本地账号，由管理员逐用户配置普通用户的模块能力。
- 审计登录、资产变更、Ping、密码查看、导入导出、备份恢复和权限变更。

第一版不包含 Active Directory、IPv6、自动资产发现、定时批量 Ping、业务端口健康检查、公共 API、移动端应用、微服务或容器编排。

## 2. 技术架构

采用 ASP.NET Core 10 模块化单体：

```text
局域网浏览器
  │ HTTPS（客户端手动信任内部根证书）
  ▼
Windows 防火墙 → IIS
                  │
                  ▼
             WebPass 应用
                  ├─ 登录与会话
                  ├─ 逐用户权限
                  ├─ 资产与地址池
                  ├─ Ping
                  ├─ 密码加解密
                  ├─ 导入导出
                  └─ 审计
                  │
                  ├─ SQL Server 2025 Express
                  └─ Windows 证书库中的数据加密证书
```

技术选型：

- ASP.NET Core 10 Razor Pages/MVC
- 少量浏览器端 JavaScript
- Entity Framework Core
- SQL Server 2025 Express
- IIS 与 .NET Hosting Bundle

应用不依赖外部互联网服务。所有授权、输入校验、密码解密和 Ping 目标校验均由后端执行；前端隐藏菜单或按钮不构成安全控制。

## 3. 账号与权限

### 3.1 登录

- 使用应用本地账号。
- 登录密码采用 Argon2id 加盐哈希，不保存可解密的登录密码。
- 初始化工具创建首个管理员，首次登录强制修改初始密码。
- 连续登录失败触发临时锁定，并记录来源 IP。
- 管理员可创建、禁用普通用户和重置其登录密码。

### 3.2 权限模型

管理员始终拥有全部权限。管理员针对每个普通用户分别勾选能力，不使用共享普通用户模板。

可委派给普通用户：

- 查看资产
- 在线新增
- 在线编辑
- 归档资产
- 执行 Ping
- 标记存活
- 导入数据
- 普通导出
- 查看服务器密码
- 管理网段
- 查看审计日志

仅管理员可执行：

- 用户与权限管理
- 加密备份导出
- 加密备份恢复
- 系统级安全配置

前端入口和后端处理器使用同一权限代码。无权限用户既看不到入口，也不能通过直接请求绕过限制。

## 4. 资产、网段与 Ping

### 4.1 服务器资产

主列表展示需求中的全部字段，并支持：

- 搜索、网段筛选、状态筛选和分页
- “仅已登记 / 显示整个地址池”切换
- 在线新增、编辑、归档
- Ping 和单独标记存活
- Excel/CSV 导入、普通导出
- 点击空闲 IP 行直接登记服务器

新增和编辑时：

- 业务 IP 必须属于一个已启用网段。
- 同一业务 IP 只能存在一条未归档记录。
- 必填项、长度和格式由后端验证。
- 服务器密码在后端立即加密。
- 审计字段由后端生成，客户端不能覆盖。

删除采用归档方式，以保留历史并允许 IP 后续重新登记。可编辑实体使用 SQL Server `rowversion` 做乐观并发控制；发生并发冲突时显示最新数据，不静默覆盖。

### 4.2 存活状态

人工存活状态为：

- 未知
- 存活
- 异常
- 停用

Ping 结果独立保存。Ping 成功只表示当前 ICMP 可达，不代表操作系统、数据库或业务服务正常。只有拥有“标记存活”权限的用户才能在 Ping 成功后单独更新状态。

### 4.3 CIDR 地址池

- 第一版只支持 IPv4。
- 输入 CIDR，例如 `10.0.0.0/24`。
- 自动排除网络地址和广播地址，`/24` 产生 254 个可用地址。
- 未登记 IP 不预先写入数据库，而是按 CIDR 动态计算并分页。
- 保存网段前预览网络地址、广播地址和可用数量。
- 网段不能相互重叠。
- 有关联服务器的网段只能禁用，解除关联后才可删除。

业务 IP 同时保存标准文本形式和用于排序的数值形式，确保 `10.0.0.9` 排在 `10.0.0.10` 前面。

### 4.4 Ping

流程：

1. 后端检查登录状态和“执行 Ping”权限。
2. 确认目标是启用网段内的 IPv4 地址。
3. 使用系统网络 API 发送 ICMP，不拼接命令行。
4. 返回成功、超时、不可达、权限不足或内部错误，以及延迟和检测时间。
5. 保存 Ping 记录，不自动修改人工状态。

Ping 使用固定超时、单用户频率限制和全局并发上限。禁止提交任意主机名、公网地址或命令行参数。

## 5. 服务器密码

服务器密码与普通资产字段分表保存。采用信封加密：

- 密码使用 AES-256-GCM 认证加密。
- 每条密码记录使用独立随机数，保存密文、随机数、认证标签和密钥版本。
- AES 主密钥由独立数据加密证书的公钥包装后保存。
- 数据加密证书位于 Windows 本机证书库，只有 IIS 应用池账号可读取私钥。
- HTTPS 证书和数据加密证书分开。
- 密钥轮换创建新版本；旧版本保留到历史密文重新加密完成。

查看流程：

1. 后端检查“查看服务器密码”权限。
2. 用户重新输入当前登录密码。
3. 验证成功后建立 5 分钟的服务器端授权窗口。
4. 后端临时解密所选密码，通过 HTTPS 返回。
5. 页面最多显示 30 秒；切页、退出或会话失效时立即移除。
6. 审计查看人、服务器、时间和来源 IP，不记录明文。

密码响应设置 `Cache-Control: no-store`，并从请求/响应正文日志中排除。HTTPS 用于防止传输链路上的被动窃听，但不能防止被控制的客户端、截屏或授权用户主动复制。

## 6. 导入、导出与备份

### 6.1 Excel/CSV 导入

支持 `.xlsx` 和 `.csv`，第一版限制为 10 MB、5,000 行。

流程：

1. 检查“导入数据”权限和文件内容类型。
2. 在受限内存中解析，不把原始上传文件写入临时磁盘。
3. 密码单元格解析后立即加密；预览只保留密文和“已提供密码”标记。
4. 展示新增、更新、跳过、错误数量和逐行错误。
5. 重复 IP、网段外 IP、缺少必填项或格式错误属于阻断错误。
6. 无阻断错误且用户确认后，在单个数据库事务内整体提交。
7. 失败时整体回滚。
8. 预览状态在取消、提交或 15 分钟超时后清除；应用重启后未提交预览失效。

明文密码只在解析单个单元格所需的最短内存生命周期内存在，不进入磁盘、日志、异常、导入任务或审计快照。系统不执行工作簿宏或公式。

### 6.2 普通导出

- 检查“普通导出”权限。
- 支持按当前筛选条件导出 `.xlsx` 或 `.csv`。
- 永远不包含服务器密码、密码密文、密钥、登录密码哈希或会话信息。
- 安全处理以 `= + - @` 开头的单元格，避免公式注入。
- 审计导出人、时间、筛选范围和数量。

### 6.3 加密备份与恢复

仅管理员可以执行，且需要二次验证。

- 备份包含资产、账号配置、权限、服务器密码密文和审计数据。
- 备份包使用独立备份口令派生的密钥进行认证加密。
- 系统不保存备份口令，且备份口令不得复用登录密码或服务器密码。
- 恢复前展示内容摘要和影响范围，恢复操作使用事务并审计。
- 数据加密证书私钥另行导出为强口令保护的 PFX，保存到受控离线介质。
- 只有数据库或备份包而没有数据加密证书时，服务器密码不可恢复。

## 7. 数据模型

| 实体 | 关键字段与约束 |
|---|---|
| User | Username 唯一、PasswordHash、IsAdministrator、IsEnabled、FailedLoginCount、LockedUntil、MustChangePassword、RowVersion |
| UserPermission | UserId、PermissionCode；组合唯一；管理员权限不依赖此表 |
| Subnet | Name、Cidr、NetworkAddress、PrefixLength、Location、IsEnabled、Notes、RowVersion；网段不得重叠 |
| ServerAsset | SubnetId、BusinessIp、BusinessIpNumber、Location、AliveStatus、ComputerName、SystemName、OSVersion、DatabaseVersion、Notes、IsArchived、创建/修改/归档信息、RowVersion |
| ServerSecret | ServerAssetId、Ciphertext、Nonce、AuthenticationTag、KeyVersion、UpdatedAt、UpdatedBy、RowVersion |
| DataEncryptionKey | KeyVersion、WrappedKey、CertificateThumbprint、ActivatedAt、RetiredAt |
| PingResult | ServerAssetId、TargetIp、Outcome、LatencyMilliseconds、ErrorCode、ExecutedAt、ExecutedBy |
| ImportJob | 文件名、类型、状态、各类行数、创建/提交时间、创建人；不保存密码内容 |
| AuditLog | 操作人、动作、对象、结果、来源 IP、关联编号、脱敏前后值、时间 |

未归档 `ServerAsset.BusinessIp` 建立唯一约束。`ServerSecret` 不提供通用列表查询，解密只能通过专用服务执行。

## 8. 审计、事务与错误

审计日志只追加，业务页面不能修改或删除。记录：

- 登录成功、失败、锁定和退出
- 用户创建、禁用、密码重置和权限变更
- 资产与网段新增、编辑、归档、禁用和删除
- Ping 与标记存活
- 密码查看
- 导入、普通导出、加密备份和恢复

日志包含操作人、动作、对象、时间、来源 IP、结果和关联编号。修改前后值必须脱敏；密码、Cookie、授权头、备份口令和密钥不得进入应用日志或审计日志。

数据库写操作使用事务。密码更新与脱敏审计在同一事务内。错误页面只显示安全说明和关联编号；详细异常写入受保护日志。Ping 超时属于正常检测结果。导入错误可显示行号、字段和原因，但不能回显密码。

## 9. Web 安全

- IIS 只提供 HTTPS 业务入口。
- HTTPS 证书包含访问所用服务器 IP。
- 客户端手动安装内部根证书；出现证书警告视为部署失败并停止使用。
- Windows 防火墙只允许指定局域网网段访问。
- SQL Server 不向局域网客户端开放，只允许本机应用连接。
- 会话 Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Strict`。
- 空闲 30 分钟退出，单次登录最长 8 小时。
- 所有状态修改请求启用 CSRF 防护。
- 登录、二次验证和敏感接口启用频率限制。
- IIS 使用独立低权限应用池账号，数据库账号只具备应用所需权限。
- 生产环境关闭详细错误和敏感请求/响应正文日志。
- 使用输出编码和内容安全策略降低 XSS 风险。

应用无法从服务端可靠判断浏览器是否信任服务器证书，因此证书信任通过部署检查、客户端操作规范和验收测试保证，而不是通过应用内伪检测保证。

## 11. 部署与运维

服务器组件：

- 受支持的 64 位 Windows Server
- IIS
- .NET 10 Hosting Bundle
- SQL Server 2025 Express
- HTTPS 证书和独立数据加密证书

交付物：

- 应用发布文件
- IIS 配置说明
- 数据库初始化和升级脚本
- 初始管理员创建工具
- 内部根证书安装说明
- 数据库、应用配置和数据加密证书备份说明
- 更新、回滚和灾难恢复手册

运行策略：

- 每日数据库备份，保留 30 天。
- 每周离线加密备份。
- 每季度执行恢复演练。
- 应用日志保留 90 天，审计日志至少保留一年。
- `/health` 只返回应用和数据库可用性，不公开版本、路径或异常。
- 更新前备份数据库，失败时恢复上一个发布目录。
- Windows Server 重启后 IIS、应用和数据库自动恢复。

## 12. 测试与验收

必须覆盖：

- CIDR 解析、网络/广播地址排除、网段重叠和 IP 数值排序
- 逐用户权限的每种允许和拒绝路径
- 登录锁定、会话过期和二次验证
- 资产增改归档、重新登记和并发冲突
- 密码加解密、密钥轮换、短时显示和日志脱敏
- Ping 合法目标、非法目标、超时、频率和并发限制
- 导入预览、阻断错误、整体提交和失败回滚
- 普通导出无密码和公式注入防护
- 加密备份导出及完整恢复
- CSRF、XSS、越权、文件伪装和超限上传
- IIS、SQL Server 和 Windows 重启后的恢复

验收标准：

1. 500 台资产、5 个网段和 5 名用户的正常负载下，局域网常规页面在 2 秒内打开。
2. 默认按业务 IP 数值升序排列。
3. `/24` 正确显示 254 个可用地址。
4. 在线新增、编辑、Ping、导入和普通导出均受逐用户权限控制。
5. Ping 成功不自动改变人工存活状态。
6. 只有获得权限并通过二次验证的用户可以短时查看服务器密码。
7. 普通导出、日志、审计和错误报告中不存在服务器密码。
8. 含密码导入完成后，正式数据库只保留密文。
9. 加密备份与恢复仅管理员可用，并能在具备正确备份口令和数据加密证书时恢复。
10. 所有敏感和数据变更操作均可审计。
11. 并发编辑不会静默覆盖。
12. Windows Server 重启后应用自动恢复。

## 13. 已确认的设计决策

- 方案 A：ASP.NET Core + IIS + SQL Server Express。
- 应用本地账号。
- 普通用户权限按用户独立配置。
- CIDR 自动排除网络地址和广播地址。
- 默认只显示已登记 IP，可切换完整地址池。
- Ping 结果与人工存活状态分离。
- 密码数据库加密保存，二次验证窗口 5 分钟，显示 30 秒。
- 普通导出不包含密码。
- 加密备份与恢复仅限管理员。
- 第一版为 IPv4、按需 Ping、约 500 台资产。
