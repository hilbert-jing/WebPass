# WebPass v1.2.0 自助修改登录密码实施计划

> **供智能体执行者使用：** 必须使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 按任务实施。本计划使用复选框（`- [ ]`）跟踪步骤。

**目标：** 为已认证且仍启用的用户增加独立、可审计的自助修改登录密码页面，不改变数据库 schema 或会话架构。

**架构：** 作用域 `PasswordChangeService` 负责查询用户、检查启用状态、验证当前密码、生成新哈希、处理并发以及原子写入成功审计。需要认证的 Razor Page 负责表单验证、敏感值清理、固定用户提示和 PRG 导航；共享布局在现有 POST 退出旁提供改密入口。

**技术栈：** .NET 10、ASP.NET Core Razor Pages、EF Core 10、SQL Server/InMemory 测试提供程序、xUnit、现有 Argon2id `IPasswordHasher`、现有 `AuditWriter`。

## 全局约束

- 不修改任何 EF Core 实体、映射、模型快照或 migration。
- 不增加撤销表、会话世代、密码时间戳或重复授权失效机制。
- 登录密码操作只使用 `IPasswordHasher.Verify` 和 `IPasswordHasher.Hash`。
- 目标用户 ID 只能来自 `ClaimTypes.NameIdentifier`，绝不接收 POST 用户 ID。
- GET 和 POST 都要求当前 `AppUser` 存在且 `IsEnabled == true`。
- 现有密码规则只有非空/非全空白；不增加长度、复杂度、历史或不同于当前密码等要求。
- 当前密码、新密码、确认密码、旧哈希、新哈希不得进入审计、状态消息、错误响应或异常文本。
- 当前及其他登录 Cookie 继续有效；保持登录锁定、Secret Reveal 和二次验证架构不变。
- 成功自助改密使用无 payload 的 `UserPasswordChange` / `User` / `Success` 审计。
- 减少测试：只测新增安全行为和状态变更，不测试 ASP.NET Core 框架机制或文档文本。

- [ ] **步骤 1：先写聚焦的失败服务测试**

使用真实 InMemory `WebPassDbContext`、真实 `Argon2PasswordHasher` 和真实 `AuditWriter`。一个成功测试证明状态变更和审计脱敏；一个理论测试覆盖用户不存在、已停用、当前密码错误、新密码全空白，并证明不修改、不写审计。

```csharp
[Fact]
public async Task Enabled_user_changes_own_password_and_writes_redacted_audit()
{
    await using var db = NewDatabase();
    var hasher = new Argon2PasswordHasher();
    var user = new AppUser
    {
        Username = "operator",
        PasswordHash = hasher.Hash("current-password"),
        MustChangePassword = true,
        FailedLoginCount = 3,
        LockedUntil = DateTimeOffset.UtcNow.AddMinutes(5),
    };
    db.Users.Add(user);
    await db.SaveChangesAsync();
    var service = new PasswordChangeService(db, hasher, new AuditWriter(db));

    var result = await service.ChangeAsync(
        user.Id, "current-password", "new-password", default);

    Assert.Equal(PasswordChangeResultKind.Success, result.Kind);
    Assert.False(hasher.Verify("current-password", user.PasswordHash));
    Assert.True(hasher.Verify("new-password", user.PasswordHash));
    Assert.False(user.MustChangePassword);
    Assert.Equal(3, user.FailedLoginCount);
    Assert.NotNull(user.LockedUntil);
    var audit = Assert.Single(db.AuditLogs);
    Assert.Equal("UserPasswordChange", audit.Action);
    Assert.Equal("User", audit.ObjectType);
    Assert.Equal(user.Id, audit.ActorUserId);
    Assert.Equal(user.Id.ToString(), audit.ObjectId);
    Assert.Equal("Success", audit.Result);
    Assert.Null(audit.Details);
}
```

拒绝理论测试使用手写预期结果，并断言原始哈希逐字节不变且 `AuditLogs` 为空。

- [ ] **步骤 3：实现最小服务**

实现结果契约：

```csharp
public enum PasswordChangeResultKind
{
    Success,
    UserUnavailable,
    IncorrectCurrentPassword,
    InvalidNewPassword,
    ConcurrencyConflict,
}

public sealed record PasswordChangeResult(PasswordChangeResultKind Kind);
```

`CanChangeAsync` 使用 `AsNoTracking` 查询 `Id` 与 `IsEnabled`。`ChangeAsync` 加载被跟踪的用户行，拒绝不可用用户和非法输入，调用 `Verify`，然后在关系型数据库中开启事务。只设置 `PasswordHash` 和 `MustChangePassword`，保存后写入以下无 payload 审计并提交：

```csharp
new AuditEntry(
    user.Id,
    "UserPasswordChange",
    "User",
    user.Id.ToString(),
    "Success",
    null)
```

只捕获 `DbUpdateConcurrencyException`，有关系型事务时回滚并返回 `ConcurrencyConflict`。其他持久化或审计异常继续抛出，由事务释放执行回滚。

在 `LoginService` 附近注册：

```csharp
builder.Services.AddScoped<PasswordChangeService>();
```

- [ ] **步骤 3：实现 Razor Page 与敏感值清理**

为 PageModel 增加 `[Authorize]` 和 `[EnableRateLimiting(SecretRateLimitPolicies.Reauthentication)]`。绑定输入模型包含当前密码、新密码、确认密码三个必填属性，并使用 `[Compare(nameof(NewPassword), ErrorMessage = "两次输入的新密码不一致。")]`。

GET 用 `Guid.TryParse` 解析 `ClaimTypes.NameIdentifier`，调用 `CanChangeAsync`，任一步失败都返回 `Forbid()`。

POST 验证身份和 `ModelState`，调用 `ChangeAsync`，按以下规则映射：

```csharp
PasswordChangeResultKind.Success => RedirectToPage(),
PasswordChangeResultKind.UserUnavailable => Forbid(),
PasswordChangeResultKind.IncorrectCurrentPassword => PageWithError(
    string.Empty, "当前密码不正确。"),
PasswordChangeResultKind.InvalidNewPassword => PageWithError(
    "Input.NewPassword", "请输入新密码。"),
PasswordChangeResultKind.ConcurrencyConflict => PageWithError(
    string.Empty, "账号信息已发生变化，请刷新后重试。"),
```

每次无效 `Page()` 响应前，把 `Input` 替换为新实例。对每个密码 ModelState key，复制错误消息、移除原项（从而移除尝试值），再只添加错误消息。成功时先设置 `TempData["StatusMessage"] = "登录密码已修改。"` 再重定向。

页面渲染三个不含显式 value 的密码输入，使用设计规定的 autocomplete token，包含 `asp-validation-summary="ModelOnly"`、字段验证提示和“修改密码”提交按钮。
